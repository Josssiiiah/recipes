# UniWind

Use this skill for Expo or React Native projects that should use Tailwind-style `className` styling through UniWind.

Prefer the free MIT-licensed UniWind setup unless the user explicitly asks for Pro features. The free version supports Tailwind CSS v4 utilities, React Native `className` props, responsive/orientation/color-scheme variants, build-time style processing, generated typings, and Expo Go compatibility. UniWind Pro adds the native C++ engine, ShadowTree updates without React re-renders, native-thread theme transitions, and className animations; it requires a custom development build and is not compatible with Expo Go.

## Before Editing

1. Inspect the project first:
   ```sh
   rg --files -g 'package.json' -g 'metro.config.*' -g 'global.css' -g 'tsconfig.json'
   ```
2. Check for existing NativeWind, Tailwind, Metro, Babel, and CSS configuration:
   ```sh
   rg -n 'uniwind|nativewind|tailwind|global.css|className' .
   ```
3. In this repo, use Bun commands by default.

Do not add NativeWind or `react-native-css` for a new UniWind setup. Do not add a Babel preset for UniWind free.

## Install

For this repo:

```sh
bun add --cwd apps/mobile uniwind tailwindcss
```

For a generic Expo app, run the equivalent package-manager command from the app root:

```sh
bun add uniwind tailwindcss
```

UniWind requires Tailwind CSS v4.

## Expo Metro Config

Create or update `metro.config.js` in the Expo app root. `withUniwindConfig` should wrap the final Metro config.

```js
const { getDefaultConfig } = require('expo/metro-config');
const { withUniwindConfig } = require('uniwind/metro');

const config = getDefaultConfig(__dirname);

module.exports = withUniwindConfig(config, {
  cssEntryFile: './src/global.css',
  dtsFile: './src/uniwind-types.d.ts',
});
```

If the project already has Metro wrappers, preserve them and make `withUniwindConfig` the outermost wrapper unless the project docs indicate otherwise.

## Global CSS

Add Tailwind and UniWind imports at the top of the CSS entry file.

```css
@import 'tailwindcss';
@import 'uniwind';
```

Keep existing project CSS variables below those imports. For this repo, `apps/mobile/src/global.css` also defines font variables used by `src/constants/theme.ts`.

## TypeScript

Point `dtsFile` at a stable generated declaration path and include it in `tsconfig.json`:

```json
{
  "include": [
    "**/*.ts",
    "**/*.tsx",
    ".expo/types/**/*.ts",
    "expo-env.d.ts",
    "src/uniwind-types.d.ts"
  ]
}
```

The declaration file is generated by UniWind. It may not exist until the Expo/Metro process runs.

## Usage

Use `className` on React Native components:

```tsx
import { Text, View } from 'react-native';

export function Example() {
  return (
    <View className="flex-1 items-center justify-center bg-white dark:bg-black">
      <Text className="text-lg font-semibold text-zinc-950 dark:text-white">
        Hello
      </Text>
    </View>
  );
}
```

UniWind supports Tailwind variants such as:

```tsx
<View className="p-4 sm:p-6 ios:pt-8 android:pt-6 dark:bg-zinc-950" />
```

For third-party components that do not accept `className`, check the current UniWind docs for `withUniwind` before writing wrappers.

## Pro Guidance

Treat Pro as an optimization, not the default.

Use free UniWind when:
- The app needs Tailwind CSS v4 utility styling.
- Expo Go support matters.
- Theme changes and responsive styles do not show measured performance problems.
- The project can handle normal React render behavior.

Consider Pro only when:
- The user explicitly wants paid Pro features.
- The app has measured performance issues from theme/style updates.
- A custom development build is already acceptable.
- Native-thread transitions or className animations are a concrete requirement.

If the user asks whether the C++ engine or "no re-renders" can be obtained for free, answer no for UniWind's Pro implementation. Use Reanimated directly for specific free animation/performance hot paths where appropriate.

## Verification

After setup, run:

```sh
bun run --cwd apps/mobile lint
```

If you need to verify the bundler, run the Expo start command long enough to catch configuration errors, then stop it:

```sh
bun run --cwd apps/mobile start --clear
```

Watch for generated `src/uniwind-types.d.ts`. If it appears, keep it when the project expects generated type declarations to be checked in; otherwise follow the repo's existing generated-file policy.
